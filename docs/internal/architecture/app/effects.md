# Эффекты

Это часть описания [архитектуры `app`](README.md). Слой эффектов выполняет то, о чём просит редьюсер виджета, потому что сам редьюсер этого сделать не может: запускает фоновую работу, читает и пишет файлы, запускает процессы и отправляет сообщения другим виджетам. Такая просьба называется *эффектом* (`XEffect`). Решений слой эффектов не принимает: их принимают редьюсеры виджетов. Слой лежит в `effects/`.

## Как понять, что код относится к эффектам

Код относится к эффектам, если он выполняет то, о чём уже решил редьюсер. Например, он:
- запускает фоновую работу через `Task::perform` и превращает её результат в интент виджета;
- читает или пишет файл через `storage` виджета или обращается во внешний мир через его `services`;
- отправляет интент другому виджету через `Task::done(AppEvent::...)`;
- сообщает пользователю об ошибке через `notifications::push`.

Если код решает, нужно ли что-то делать, это редьюсер виджета. Если код передаёт интент в `reduce`, это [доставка](app.md#доставка), часть приложения.

У каждого виджета свой *файл эффектов* `effects/x.rs`, даже если у его `XEffect` пока нет вариантов: так все виджеты устроены одинаково, и генератор всегда создаёт этот файл. Кроме файлов виджетов, в слое есть [эффекты запуска](#эффекты-запуска) `effects/startup.rs`.

Как событие доходит до файла эффектов, показывает [«Путь события»](README.md#путь-события), а как выглядит файл эффектов, показывает [`effects/notes.rs`](widgets.md#effectsnotesrs) в примере виджета.

## Что эффекты могут импортировать

Эффекты могут импортировать все слои, в том числе модули ввода-вывода из общего кода. `services` и `storage` виджета вызывает только слой эффектов, и только у своего виджета: `effects/x.rs` вызывает их у виджета `x`, см. [«Что видно снаружи»](widgets.md#что-видно-снаружи). Полная таблица лежит в разделе [«Кто что импортирует»](README.md#кто-что-импортирует).

`AppEvent` файл эффектов импортирует из `event.rs`, а не из доставки: `use crate::event::AppEvent;`. Это тип событий всего приложения, он относится к слою приложения, см. [«Сообщения и отметки»](app.md#сообщения-и-отметки). Файлы эффектов от доставки не зависят: их `run` вызывает `dispatch/mod.rs`, а не наоборот.

Запрет clippy на фоновую работу, файлы и процессы снят на объявлении `mod effects`, поэтому файл эффектов может запускать фоновую работу, например через `Task::perform`. На объявлении `mod dispatch` этот запрет не снят: доставка ввод-вывод не выполняет.

## Правила для файла эффектов

Сейчас в тесте архитектуры правил нет, поэтому эти правила проверяет ревью.

- `effects/x.rs` единственное место, где выполняются эффекты виджета `x`. Его `run` вызывает только `dispatch/mod.rs`, когда приходит `XEvent::Effect`. Другие файлы эффектов из него вызывают только `notifications::push` из `effects/notifications.rs`: так любой файл эффектов сообщает пользователю об ошибке.
- Файл эффектов никогда не вызывает `reduce` и точку входа доставки. Сообщение другому виджету он отправляет через `Task::done(AppEvent::...)`, а результат фоновой работы возвращает интентом своего виджета. Такое событие проходит [путь события](README.md#путь-события) с начала.
- Файл эффектов не меняет никакого состояния. Состояние виджета меняет только его `reduce`, а поля самого приложения, которые не принадлежат ни одному виджету, меняет только [доставка](app.md#доставка) в `dispatch/mod.rs`. Если результат эффекта нужно записать в приложение, файл эффектов отправляет его событием приложения. Например, эффекты запуска читают имя компьютера и отправляют его событием, а доставка записывает его в приложение.
- Файл эффектов выбирает, что делать, только по виду эффекта, а не по состоянию виджетов. Состояние он читает только для того, чтобы собрать данные, которые нужны эффекту. Решения принимает редьюсер и сообщает о них эффектами. Например, в `notes` правило «не читать файл, пока идёт чтение» проверяет редьюсер через `begin_loading`, а `effects/notes.rs` только выполняет `NotesEffect::LoadRequested`.
- Если для эффекта нет данных, файл эффектов ничего не отправляет: это не решение, а отсутствие данных. Например, на `TerminalWorkspaceEffect::SyncExplorer` интент `ExplorerIntent::SyncRoot` уходит, только если у активной вкладки есть локальная папка.
- Параметр типа `XEffect` называется `effect`, как в `run(effect: NotesEffect)`, а параметр типа `XIntent` называется `intent`. Так же они называются в `dispatch/`.
- Эффекты дочерних виджетов большого виджета выполняет файл эффектов родителя: для каждого дочернего виджета в нём есть своя приватная функция, см. [«События дочернего виджета»](widgets.md#события-дочернего-виджета).

## Эффекты запуска

`effects/startup.rs` выполняет ввод-вывод события `AppEvent::IcedReady`, которое приходит, когда окно готово: записывает файлы интеграции shell и читает имя компьютера. Результат он отправляет по цепочке тремя событиями: `ShellIntegrated` с сессией shell, `HostNameRead` с именем компьютера и интент открыть первую вкладку. `dispatch/mod.rs` записывает первые два в приложение, а цепочка гарантирует, что это случится до открытия вкладки. Этот файл не принадлежит ни одному виджету, его вызывает `dispatch/mod.rs`.

При старте, кроме `load()` виджетов, ничего не читается и не пишется: `App::new` берёт сессию shell без интеграции и не знает имени компьютера. Первая вкладка открывается только после эффектов запуска, поэтому первый терминал уже запускается с интеграцией shell.
