## Subscription or API key

A profile pays either with a subscription or with an API key, and the dashboard shows different
numbers for each. OTTY tells which one it is from the profile's files:

| The profile is   | When                                                                       | The dashboard shows |
| ---------------- | -------------------------------------------------------------------------- | ------------------- |
| **Subscription** | A ChatGPT login, such as Plus or Pro, or a workspace that pays with credits. | Limits (usage windows or credits), Tokens |
| **API key** | The profile's `auth.json` says it logs in with an API key. | Money, Prices, Tokens |

## Limits

### ChatGPT usage API

<Badge text="network" variant="caution" />

- **Does:** Reads the login token Codex keeps in `auth.json` in the profile folder and asks ChatGPT
  for the limits of the account. OTTY never writes or renews the token.
- **Sends:** One `GET` to `https://chatgpt.com/backend-api/wham/usage`, with that token, the
  workspace id of the login, the header `Accept` and OTTY's `User-Agent`. When `chatgpt_base_url` in
  the profile's `config.toml` names another server, the request goes there: to `/wham/usage` on a
  server with `/backend-api`, to `/api/codex/usage` on any other.
- **Sends, for credits:** When the answer says credits are on but gives no number, the server has
  `/backend-api`, and the answer is about the account of this login, one more `GET` asks for the
  balance of the account. When the answer also has a spending limit and the plan is not a personal
  one, another `GET` asks for the credits used this month. Both carry the same headers.
- **When:** First, at every read of the limits. A missing, expired or refused login is "login
  expired"; OTTY sees an expired token in the file itself and then sends nothing.

### Codex app-server

<Badge text="runs the agent" variant="note" />

- **Does:** Starts `codex app-server` through your login shell, with the profile folder, in
  read-only mode, and asks it only for the limits of its login; never for the list of sessions. The
  program is stopped right after.
- **Sends:** OTTY talks only to that program on your computer. How Codex gets the answer is up to
  Codex.
- **When:** When the request above gives no answer, and only while Agents mode is on screen. It
  gives up after 10 seconds. Its answer is not kept: while the request above fails, OTTY starts the
  program again at every read.

### Latest Codex session

<Badge text="local" variant="success" />

- **Does:** After each answer of the model, Codex writes the limits it got into the session file.
  OTTY takes the latest record from the 10 newest session files. These limits are as old as the
  record; **Updated** shows its time.
- **Sends:** Nothing: the files are read on your computer.
- **When:** When neither source above answers.

## Tokens

### Session files

<Badge text="local" variant="success" />

- **Does:** Counts the tokens of every session file in `sessions/` and `archived_sessions/` in the
  profile folder, plain and compressed, helper agents included. Agents mode lists only the sessions
  you started.
- **Sends:** Nothing: the files are read on your computer.
- **When:** At every read of the tokens.

## Money

### Estimate

<Badge text="network" variant="caution" /> or <Badge text="local" variant="success" />

- **Does:** Tokens of the session files × the LiteLLM list prices. See [the money
  estimate](../../overview/#the-money-estimate). OTTY does not read the bill of an OpenAI
  organization.
- **Sends:** A plain `GET` of the [LiteLLM price file](../../overview/#the-money-estimate), with no
  login and no account data. Within a day of the last good read OTTY uses its kept copy and sends
  nothing; when a read fails, it falls back to that copy. The token counts stay on your computer.
- **When:** At every read of the money of an API key profile.

## What it changes in the agent's files

<Aside type="tip">
OTTY only reads the files. It starts `codex app-server` in read-only mode and asks it only for the
limits, so the model runs no commands. Codex itself may still write its own logs and state, or renew
its login token, as on any start.
</Aside>
