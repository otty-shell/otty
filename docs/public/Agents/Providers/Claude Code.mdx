## Subscription or API key

A profile pays either with a subscription or with an API key, and the dashboard shows different
numbers for each. OTTY tells which one it is from the profile's files:

| The profile is   | When                                                                       | The dashboard shows |
| ---------------- | -------------------------------------------------------------------------- | ------------------- |
| **Subscription** | A Claude plan, such as Pro or Max. | Limits, Tokens |
| **API key** | The profile's `settings.json` has `ANTHROPIC_API_KEY` in `env` or an `apiKeyHelper`, `.claude.json` has a `primaryApiKey`, or the login is a Console organization that pays in advance. A key set only in your shell or in `settings.local.json` is not seen. | Money, Prices, Tokens |

## Limits

### Anthropic usage API

<Badge text="network" variant="caution" />

- **Does:** Reads the login token Claude Code keeps in `.credentials.json` in the profile folder and
  asks Anthropic for the limits of the account. OTTY never writes, renews or keeps the token.
- **Sends:** One `GET` to `https://api.anthropic.com/api/oauth/usage` with that token, the headers
  `Accept` and `anthropic-beta`, and OTTY's `User-Agent`.
- **When:** First, at every read of the limits. An expired or refused token is "login expired" and
  the next source is tried. No token file (on macOS the login may be in the Keychain), or a token
  that may not read the usage, is "not available".

### Claude Code /usage

<Badge text="runs the agent" variant="note" />

- **Does:** Starts `claude` in a hidden terminal through your login shell, with the profile folder,
  types `/usage`, reads the limits from the screen and stops the program. OTTY sends no prompt, and
  `claude` runs with no tool allowed without asking, none of your MCP servers, no hooks, no remote
  control and no automatic update, in a folder of its own: `~/.cache/otty/agent-probe`, which OTTY
  creates.
- **Sends:** Nothing from OTTY. Claude Code makes its own requests with its own login, as on any
  start, and may renew its login token.
- **When:** When the direct request gives no answer, and only while Agents mode is on screen. It
  gives up after 30 seconds. The answer is reused for 4.5 minutes, so pressing Refresh again does
  not start `claude` again. When `claude` asks to log in or shows another question OTTY recognizes,
  other than whether to trust its own folder, OTTY types nothing and stops it.

## Tokens

### Session files

<Badge text="local" variant="success" />

- **Does:** Counts the tokens of every session file in `projects/` in the profile folder, helper
  agents included. Agents mode lists only the sessions you started.
- **Sends:** Nothing: the files are read on your computer.
- **When:** At every read of the tokens.

## Money

### Anthropic cost report

<Badge text="network" variant="caution" />

- **Does:** Reads the bill of your whole organization, not only of this profile. Point OTTY at an
  admin key in the **Edit** dialog of a profile logged in to the organization: a file that holds
  it, or the name of an environment variable. The key belongs to the organization, so every profile
  of it shares it, and the bill is read once for all of them. OTTY keeps only that path or name,
  never the key.
- **Sends:** `GET` requests to `https://api.anthropic.com/v1/organizations/cost_report` for the 31
  days up to today, with the admin key in `x-api-key`, the headers `anthropic-version` and `Accept`,
  and OTTY's `User-Agent`. The key is read for the request and dropped right after.
- **When:** First, when the organization has an admin key; without one it is "not available". The days
  are the days of Anthropic's report, in UTC.

### Estimate

<Badge text="network" variant="caution" /> or <Badge text="local" variant="success" />

- **Does:** Tokens of the session files × the LiteLLM list prices. See [the money
  estimate](../../overview/#the-money-estimate).
- **Sends:** A plain `GET` of the [LiteLLM price file](../../overview/#the-money-estimate), with no
  login and no account data. Within a day of the last good read OTTY uses its kept copy and sends
  nothing; when a read fails, it falls back to that copy. The token counts stay on your computer.
- **When:** When the cost report gives no answer or there is no admin key; "not needed" while the
  cost report answers.

## What it changes in the agent's files

<Aside type="caution" title="Only the hidden run of claude changes something">
- Claude Code asks whether to trust the folder it runs in. OTTY answers "Yes" for its own folder,
  `~/.cache/otty/agent-probe`, and only for it. Claude Code saves the answer in the profile's
  `.claude.json`; for the default profile that is `~/.claude.json`, next to `~/.claude`.
- Claude Code leaves a session file of that run in the profile folder. OTTY removes the session
  files of its own folder, and that folder once it is empty, and nothing else.
- Claude Code may renew its own login token, and update its own records as on any start.
</Aside>

All other sources only read.
