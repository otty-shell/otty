Agents mode shows two things side by side:

- **Accounts**: where you pay. Subscriptions with their limits and credits, keys with the money left
  or spent on them.
- **Profiles**: what you work with. Each agent and its folder, with its sessions, projects and the
  tokens and money they used.

OTTY finds both by itself in the agents' folders on your computer. You act only where nothing else
works: allow the system keyring, give a key a plugin asks for, add a key no agent uses, or log in
again in an agent.

OTTY has no code for any agent or provider by name. What it knows comes from
[plugins](../plugins/); the five [official plugins](../official-plugins/anthropic/) are built in,
so Claude Code, Codex, OpenCode, Anthropic, OpenAI, DeepSeek and OpenRouter work with no setup.

## Accounts and profiles

One account can be used by several agents, and one agent can pay through several accounts. A
profile's page lists its accounts under **Pays through**; an account's page lists its profiles
under **Used by**.

| Word        | Means                                                                                                  |
| ----------- | ------------------------------------------------------------------------------------------------------ |
| **Profile** | One agent with one config folder. `~/.claude` and `~/.claude-work` are two profiles of Claude Code.   |
| **Account** | One login or key at a provider: a Claude login, a ChatGPT login, an organization, a DeepSeek key.     |
| **Need**    | A task only you can do, with one button. Needs are listed on the pages and under **Needs you**.      |

OTTY finds the default folder of each agent and the other folders of the same agent in your home
folder that hold a login or sessions, such as `~/.codex-work`. Logins with the same account id,
organization or email are one account; keys are one account when their fingerprint (a hash, kept in
memory only) is the same. So a ChatGPT login used by Codex and OpenCode is one row, read once.

On the first start, **Found by OTTY** lists the profiles and accounts it found and what needs you.
All accounts → "⋯" → **Show Found by OTTY** opens it again.

## The left panel

| Section      | Lists                                                                                     | "+" opens         |
| ------------ | ----------------------------------------------------------------------------------------- | ----------------- |
| **Accounts** | **All accounts**, then each account with its number now: "62 % used", "¥110 left", "$44.87 this month", or "$42.10 · estimate, list prices" for an [estimate](#the-money). | Add account |
| **Profiles** | **All profiles**, then each profile with today's tokens, or its state: "needs login", "format changed". | Add profile |
| **Projects** | The project folders of all agents, with search and filters.                               | New session       |

**All accounts** and **All profiles** are tables with their **Needs you** list.

## The pages

| Page        | Shows                                                                                                                       |
| ----------- | --------------------------------------------------------------------------------------------------------------------------- |
| **Account** | Needs from you; **Limits**, **Credits** or **Money** (Left, Spent this month, Key limit); **Used by**; **Account info**: provider, email or key, plan, where it was found, **Read by** (the plugin and its version). |
| **Profile** | Needs from you; the usage block; **Pays through**; **Profile info**: agent, version, folder, projects, sessions, **Read by**. |
| **Project** | Path, profiles and accounts, then the sessions of all profiles. Double click or Enter continues a session in a terminal tab; the menu also has Continue in a split, Copy resume command, Copy session ID and Show statistics. **Project statistics** opens the numbers of the whole project. |

The **usage block** has a period (Today, 7 days, 30 days), a measure (Tokens or Money) and the tabs
**By project**, **By model** and **By account**. A choice that makes no sense is off and says why,
such as Money for a subscription ("Paid by a subscription: there is no price per request").

## Needs

A need is a task only you can do, with one button. It shows in **Needs from you** on the page of
the account or profile, and in the **Needs you** list. Two kinds of needs come from two places:

- **OTTY asks** about plugins and about its own permissions, since a plugin can not tell these
  about itself. These needs carry no plugin name.
- **A plugin asks** for everything about its agent or provider: a login, a key, a key of another
  kind to read a bill. OTTY shows the need as the plugin wrote it, with a small label naming the
  plugin, such as "OpenAI plugin", so you see who asks.

### What OTTY asks

| Need                                   | When                                                                  | Button                  |
| -------------------------------------- | --------------------------------------------------------------------- | ----------------------- |
| Plugin update needs your OK            | A newer version of a plugin asks for new permissions.                 | Review                  |
| Plugin part is off                     | The part that reads this account is turned off.                       | Turn on                 |
| No provider plugin                     | A key was found for a host no plugin serves.                          | Add plugin…             |
| *Plugin* could not read                | A plugin part failed, ran out of time or was paused; the last good numbers stay. | Copy report  |
| *Agent version* changed its session files | The plugin no longer understands most records ([below](#format-changed)). | Copy report, Open plugin repository |
| [System keyring](#the-system-keyring)  | A plugin part reads keys from the system keyring.                     | Allow keyring           |
| The login was refused                  | A provider refused a login, and the plugin of the agent that keeps it says nothing about it ([below](#a-refused-login)). | None |

### What a plugin asks

The title and the text are the plugin's. The button does one of four things:

| Button             | Does                                                                                         |
| ------------------ | -------------------------------------------------------------------------------------------- |
| Run *command*      | Runs the command in a new terminal tab, such as `codex login`, or the agent itself so it renews its login. |
| *Name of the key*… | Opens a field for a key the plugin needs, such as **Admin key…**, with the plugin's hint and a link to the page where the key is made. You type the path of a file that holds the key, or the name of an environment variable. OTTY saves only that path or name, never the key, and the plugin gets the key only as a handle. |
| Open *site*        | Opens an `https` page in your browser, such as the page where you make a new key.           |
| Copy report        | Copies a text the plugin wrote, such as a report for its author.                             |

What each official plugin asks for is on its page: [Anthropic](../official-plugins/anthropic/#what-it-asks-you-for),
[OpenAI](../official-plugins/openai/#what-it-asks-you-for), [OpenCode](../official-plugins/opencode/#what-it-asks-you-for),
[DeepSeek](../official-plugins/deepseek/#what-it-asks-you-for), [OpenRouter](../official-plugins/openrouter/#what-it-asks-you-for).

### A refused login

A provider part may read a login that an agent keeps, such as a ChatGPT login of Codex. It does not
know which agent keeps it, so when the provider refuses the login or it expired, OTTY asks the
plugin of the agent whose profile holds it, and shows that plugin's need on the profile. A ChatGPT
login kept only by OpenCode shows OpenCode's **Run opencode auth login**, not Codex's. The same need
from several reads of one profile shows once.

When the agent's plugin gives no need, fails or runs out of time, OTTY shows its own need **The
login was refused**, which names the provider and the profile and has no button: log in again with
that agent yourself, then refresh. OTTY never renews a login it found in an agent.

### The language of a need

A plugin writes its needs in the language of OTTY's interface when it has translations, else in
English. The five official plugins have all ten languages of OTTY. When you change the language,
OTTY tells each plugin that has translations and reads Agents mode again at once, so their needs
change without a restart.

## Your choices

"⋯" on a page and a right click on a row open the same menu.

- **Rename…** gives an account or a profile a name of your own. **Hide** stops OTTY from reading it
  and takes it out of the lists; "⋯" on All accounts or All profiles → **Show hidden** brings it back.
  An account that is only a key found in an agent can not be renamed or hidden yet.
- **Open usage page** opens the provider's own usage page of the account.
- **Add account** is the last resort: a key no agent uses, for the money left (DeepSeek, OpenRouter),
  or an admin key for the bill of an Anthropic or OpenAI organization. OTTY saves only the path of
  the file that holds the key, or the name of the environment variable, never the key. **Edit
  key…** and **Remove** on an added account change or drop it.
- A key a plugin asks for in a need, such as the admin key of an organization that an agent found,
  is given with the need's button and kept the same way.

Names, hidden items, added accounts, the places of the keys you gave and whether the keyring may be
read are kept in `~/.config/otty/agents.json`.

### The system keyring

A plugin part may read keys that an agent keeps in the system keyring. OTTY lets it read nothing
there until you allow it once (need **Allow keyring**), and asks only while such a part is on. None
of the official plugins reads the keyring, so with them alone this need does not appear.

### Format changed

Agents change their files without notice. Each plugin part counts the records it saw and the ones it
understood. When the newest files hold at least 5 records of the kind it reads and fewer than half
are understood, the profile shows **format changed** instead of quietly showing fewer tokens:

- its last good numbers stay, greyed, with their time; other profiles and accounts work as usual;
- the need names the agent's version and the plugin: "Codex 0.170.0 changed its session files. The
  OpenAI plugin 0.2.0 reads them up to Codex 0.169.0.";
- **Copy report** copies a report for the plugin's author: agent, version, tested version, plugin,
  folder, file kind, the counts and the names of the fields. Never a value, key or session text.

The fix is a new release of the plugin, not of OTTY.

## How old a number is

A number on a page is the latest one OTTY read, with its time ("Updated 2 min ago"). Where a plugin
reads it from is the plugin's business: an agent's own program, its files or a server. OTTY keeps
one order of its own, because the parts can come from different plugins: for each account it asks
the provider's plugin part first, then the agent's part.

- When a read fails, the last good numbers stay, greyed, with their time, and a line under them
  says why. When you can do something, it is in **Needs from you**: log in again, update the
  plugin, give a key.
- Money that is an estimate at the [list prices](#the-money), not the provider's bill, has the mark
  **estimate, list prices** under it, on the account page and under the usage block in Money; its
  tooltip says when the prices are from. Where there is no room under the sum (the left panel, the
  All accounts table, Found by OTTY, the account chips, the Cost of a project) the mark follows the
  sum: "$42.10 · estimate, list prices". Money with no mark is the bill or the cost the agent wrote.
- **Read by** in Account info and Profile info names the plugin and its version. What a plugin
  failed to read last is on its card on the [Plugins](../plugins/) page.

## When OTTY reads

| When                     | What OTTY reads                                                                                            |
| ------------------------ | ---------------------------------------------------------------------------------------------------------- |
| OTTY starts              | Profiles first, then sessions, limits, tokens and account numbers together; prices and bills after limits. |
| Agents mode is on screen | Limits and bills again every 5 minutes. Opening the mode reads again what is older than 5 minutes.         |
| You press **Refresh**    | Profiles, then everything else.                                                                            |

What a read gave stays on screen until the next read answers: a Refresh or a later read never
empties a page or brings back the spinner, which shows only before the first read of the profiles.

<Aside>
While Agents mode is away, OTTY never starts an agent's program. A plugin that starts one, such as
`codex app-server` or Claude Code's `/usage`, runs it at most once in about 5 minutes per profile;
a Refresh in between shows its last answer.
</Aside>

## The money

Money comes, best first, from the provider's bill (for an Anthropic or OpenAI organization, with an
admin key), from the cost the agent wrote itself (OpenCode does), or from an **estimate**:

> money = tokens of each model × the list price of that model where it was served

The price of a model depends on who served it: the maker itself, a cloud or a reseller such as
OpenRouter. Each plugin says who served each answer, as the agent wrote it, and OTTY picks the
price: the list price of who served the answer, else the maker's own list price of the model, else
no price. OTTY never takes the price of a similar model instead.

The prices cover input, cached input, writing to the cache and output, with the higher prices of a
long prompt where a model has them. Discounts are not known to OTTY. A model with no price adds
nothing, and a line under the money says how many requests of this month have no price. There is
no budget: OTTY only shows the money.

The prices come from the open source [LiteLLM](https://github.com/BerriAI/litellm) price table, read
by OTTY once for all plugins, at most once a day and only while a profile pays with an API key.
Plugins report tokens; OTTY prices them. The last good copy is kept in
`~/.cache/otty/prices/litellm.json` for when a read fails. Days follow your time zone; a bill keeps
the UTC days of the provider's report.

What OTTY and each plugin read and send is on
[What OTTY reads and sends](../what-otty-reads-and-sends/).
