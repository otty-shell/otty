A **plugin** teaches OTTY to read one or more coding agents or model providers. It is a small
WebAssembly program from its author's GitHub repository, or from a folder on your computer, that runs
inside OTTY in a closed box: it can touch nothing on your computer or the network except what its
permissions list.

OTTY comes with no plugins. On the first start Plugins mode is empty and Agents mode says that no
agent plugin is on, with **Manage plugins…**. You install the plugins you want, and they stay
installed between starts.

## Plugins mode

Plugins is a mode of its own, like Agents mode. It is not pinned on the first start: open it from
**All modes** ("⋯" next to the mode switcher, <kbd>Ctrl</kbd> <kbd>Shift</kbd> <kbd>M</kbd> on
Linux, <kbd>Cmd</kbd> <kbd>Shift</kbd> <kbd>M</kbd> on macOS), and pin it there to keep it in the
switcher. Agents mode opens it too: **Manage plugins…** with nothing selected, "Read by" and the
needs with their plugin selected.

- **On the left**, the installed plugins under **Installed**, each with its icon, name and mark, a
  search field that keeps the plugins whose names hold what you type, and **Add plugin** in the
  header, a `+` with a chevron like the New session and New launch buttons of Terminal mode: `+`
  opens **Add plugin…**, and the chevron opens a menu with **Add plugin…** (from a repository) and
  **Add plugin from folder…**. A right click on a plugin opens a menu with the actions of its page:
  **Check for updates** (or **Reload** for a local plugin), **Review update…** while an update
  waits, **Show log** and **Remove…**, which asks first as on the page. The right click does not
  change which plugin is selected, and **Review update…** shows the plugin's page with the update
  dialog, as **Review** does.
- **In the main area**, the page of the selected plugin: its version with a small tag of who
  reviewed it (**Official**, **Community** or **Local**; point at it for what it means), what the
  plugin says it does, its authors and source, each of its parts as a card, and **Check for
  updates** (or **Reload** for a local plugin), **Show log** (what the plugin wrote to its log) and
  **Remove**. The source is the link of the repository the plugin came from, which opens it in your
  browser, or its folder for a local plugin. With nothing selected, or nothing installed, the main
  area says what to do and has both ways to add a plugin.

## Plugins and parts

A plugin has one or more **parts**. Each part belongs to a domain of OTTY, the place of the window
it fills; the plugins of Agents mode have parts of the **Agents** domain: an **agent part** reads one
agent's folders, a **provider part** reads the accounts of one provider. On the page of a plugin
each part is a card: its name, a small tag with its kind (**Agent** or **Provider**), its health
(**Working**, **Paused** or **Off**), its switch at the right end, and under them one sentence
from the plugin on what the part does, such as "Finds Codex profiles, sessions, tokens and
logins.", with **Can access (N)** (N is the number of places it can reach), which opens what it can
access. Each part has its own permissions and its own switch.

Each plugin on the left shows its icon, its name and a mark of where it comes from, and its page
shows the same mark as a tag after its version; the **Community** tag is in the warning color:

| Mark          | Means                                                                                                  |
| ------------- | ------------------------------------------------------------------------------------------------------ |
| **Official**  | From a repository of the OTTY team (`github.com/otty-shell/`), reviewed by the team.                   |
| **Community** | From anyone else's repository, reviewed by its author only.                                            |
| **Local**     | From a folder on this computer: a plugin you built, or an official plugin from a copy of the OTTY repository. Never updated on its own. |

After the mark, a sign says when a plugin needs a look:

| Sign       | Means                                                                       |
| ---------- | --------------------------------------------------------------------------- |
| **failed** | A part is paused after three failures, or the latest check or change failed. |
| **update** | A newer version waits for your OK.                                          |
| **off**    | Every part of the plugin is off.                                            |

## Add a plugin

1. **Add plugin…** (`+` on the left, or **Add plugin…** in the menu of its chevron) → paste the
   link of the plugin's GitHub repository, such as `https://github.com/owner/otty-plugin-name` →
   **Next**. Only GitHub links work.
2. OTTY takes the newest release with a semver tag (`v1.2.0` or `1.2.0`) that this OTTY can run;
   pre-releases are skipped. A repository with no such release is refused.
3. The install dialog shows the name, version and authors, how far the plugin is trusted (for a
   community plugin, "Community plugin: reviewed by its author only" as a warning), and each part
   as a card: its name, the tag of its kind, what it does, and under **Can access** its permissions,
   grouped as in the Can access dialog of the plugin's page. Press **Install**.

OTTY checks everything before it runs the plugin: the manifest, the size of the files (the `.wasm`
at most 20 MiB), the icons (SVG, at most 16 KiB, no scripts, links or embedded images), and that the
`.wasm` uses nothing but what OTTY gives plugins. A check that fails says why, and nothing is
installed.

**Add plugin from folder…** (in the menu of the chevron next to `+` on the left) installs a plugin
built on this computer: type the folder that holds its `otty-plugin.toml`, its `.wasm` and its
icons, then **Next** and **Install**. For a plugin of your own, see [Write a plugin](../write-a-plugin/#try-it-in-otty).

## Install the official plugins

The [official plugins](../official-plugins/anthropic/) do not have repositories of their own yet.
Until they do, install them from a copy of the OTTY repository, where each one is built into
`assets/plugins/<id>/`:

1. Get the repository: `git clone https://github.com/otty-shell/otty`.
2. **Add plugin from folder…** → pick `assets/plugins/openai/` (or `anthropic`, `opencode`,
   `deepseek`, `openrouter`) → **Next** → **Install**.

A plugin installed this way is marked **Local**: it changes only when you pull a newer copy and
press **Reload** on its page. Once an official plugin has its own repository, add it with
**Add plugin…** and the link of that repository instead; it is then marked **Official** and updates
from its releases.

## Permissions

Permissions are listed per part, and **apply per part**: while OTTY asks one part for something,
only that part's permissions count. The OpenAI provider part may read the session files of Codex,
where Codex writes the limits it was last told, but not the rest of `~/.codex`, which the Codex
part of the same plugin reads. A provider part that reads limits by asking the agent itself lists
the program and the files it needs, under its own name.

**Can access (N)** on the card of a part opens the dialog "*Part* can access", such as "Anthropic
can access": the line "Only this is open to the part, OTTY refuses everything else.", then the
part's permissions grouped by
what they reach, one row per group with a thin line between rows: the group and one muted line on
what it means on the left, its places on the right, one per line. A group the part does not use is
left out, and a part that asks for nothing says "Asks for no permissions" on its card, with no
button. The install and update dialogs show the same groups under **Can access** of each part.

| Group               | Its line                                   | Its places                                                     |
| ------------------- | ------------------------------------------ | -------------------------------------------------------------- |
| **Files**           | Read only                                  | Files it reads, such as `~/.codex*/**`.                        |
| **Changes files**   | May write and delete                       | Files it writes and deletes, such as `~/.claude*/projects/*--cache-otty-agent-probe/*.jsonl`. |
| **Databases**       | SQLite, read only                          | SQLite databases it reads, such as `~/.local/share/opencode/opencode.db`. |
| **Variables**       | Environment variables, read only           | Environment variables it reads, such as `CODEX_HOME`.          |
| **Programs**        | Runs them and reads the output             | Programs it runs, such as `codex -s read-only -a never app-server`. |
| **Hidden terminal** | Runs without a visible tab and reads the output | Programs it runs in a terminal you do not see, such as `opencode stats`. |
| **Keyring**         | Entries of the system keyring, given as handles | Entries it reads once you allow the keyring.              |
| **Logins**          | Where your logins are kept, given as handles | A file such as `~/.codex*/auth.json`, a database, or a variable such as `OPENAI_API_KEY`. |
| **Sites**           | Sends requests only to these               | Sites such as `chatgpt.com`.                                   |
| **Found logins**    | Logins and keys of Anthropic accounts that agent plugins found, given as handles | A provider part's own: "Anthropic accounts", the logins and keys agent plugins found in your agents, and "keys for `anthropic.com`", the keys found for each of its sites. |

OTTY gives every login and key to a plugin only as a **handle**: it stands in for the key or login
token, the plugin can put it into a request but never reads the key itself. See
[What OTTY reads and sends](../what-otty-reads-and-sends/).

You grant the whole list or nothing; then you can turn single parts off. **Can access** on the card
of a part shows its permissions at any time.

## When two plugins serve the same thing

Nothing is asked. When two plugins both have a provider part for one provider, or for one host
under two provider ids, both read its accounts: one login or key is then two accounts in Agents
mode, each named with its plugin, such as "Anthropic · you@example.com (Anthropic Fork)", or
"you@example.com (Anthropic Fork)" in the left panel. This is
also true of an account you added, when both plugins offer **Add account** for its provider: you
give the key once, and each plugin reads its own copy. Hide the one you do not want; each copy hides
alone, and a hidden copy is read by nobody and left out of every total, while the other stays. When
two plugins have an agent part for the same agent, the one installed first reads it; turn the other
part off on its plugin's page.

## Turn parts on and off

The switch of a part stops or starts only that part; its files and your settings stay. When an agent
part is off, its profiles leave Agents mode; when a provider part is off, its accounts keep their
tokens and estimates but lose their limits and balances, and show the need **Plugin part is off**.

A part whose reads fail three times in a row is **Paused** ("Paused after three failures" when you
point at it), and **Try again** shows next to it; the plugin's other parts keep working. **Try
again** starts it again, as does the next start of OTTY.

Under a part, its card shows the last call that failed or that OTTY refused, with its time and
kind: "Last failure 5 min ago: numbers, the plugin did not finish in time". It never shows a
value, a key or session text. **Copy report** copies the report for the plugin's author. This is the
place to look when a plugin gives no numbers.

## Updates

Once a day, and when you press **Check for updates**, OTTY looks for a newer release of each plugin
added from GitHub and takes the newest one it can run. What it did is a notification at the top of
the window, kept in the list under the bell:

| The new release                          | What happens                                                                         |
| ---------------------------------------- | ------------------------------------------------------------------------------------ |
| Asks for nothing new                     | Installs on its own. A notification says "Plugin OpenAI updated to 0.5.0".           |
| Asks for new permissions or has a new part | Waits. The plugin is signed **update** on the left, its page says "0.5.0 asks for new permissions" with **Review**, and Agents mode shows **Plugin update needs your OK**, whose **Review** opens the dialog in Plugins mode. The dialog shows what each changed part can access, marks a new permission **new** and one the new version drops **no longer**. The installed version keeps running until you press **Update**, which says "Plugin OpenAI updated to 0.5.0". |
| Needs a newer OTTY                       | Skipped. Its page says "0.6.0 needs a newer OTTY"; the installed version keeps running. |
| Changed its files after you installed it | Refused: "The release v1.2.0 of OpenCode changed after it was installed. OTTY keeps the installed copy." |
| There is nothing newer                   | After **Check for updates**, a notification says "Plugin OpenAI is up to date". The daily check says nothing. |

When the check fails, an error notification says why, such as "Plugin OpenAI could not check for
updates: GitHub refuses more requests from this computer for now. Try again in an hour.", and the
plugin is signed **failed** on the left.

Parts keep their on or off state across updates, and a new part is on. Local plugins are never checked;
**Reload** reads their folder again. A notification says "Plugin OpenCode reloaded" when the version
is the same, or "Plugin OpenCode updated to 0.1.5" when it changed; when the new copy asks for more,
the same dialog shows. A reload that fails is an error notification: "Plugin OpenCode could not be
reloaded: …".

## Remove

**Remove** deletes the plugin's files and its compiled copy. The names and hidden items of Agents
mode stay, and come back if you add the plugin again.

## When a plugin or part is missing

Accounts and profiles do not depend on a provider plugin: OTTY joins accounts and adds up tokens
itself.

| Situation                         | What you see                                                                          |
| --------------------------------- | ------------------------------------------------------------------------------------- |
| No plugin reads an account        | The account is listed by its provider or the host of its key, with a letter icon, its tokens and an estimate, but no limits or balance. Account info: "Read by: no plugin". The need **No provider plugin** says no installed plugin reads it → **Add plugin…**. |
| A provider part is off            | The same, "Read by: DeepSeek 0.1.1 (off)", need **Plugin part is off** → **Turn on**. |
| An agent part is off, or its plugin removed | Its profiles leave the lists; accounts found only there leave too. Names and hidden items are kept. |
| A plugin is updated               | Nothing moves. "Read by" shows the new version.                                       |
| A part fails                      | The last good numbers stay, greyed. Need "*Plugin version* could not read …" with **Copy report**. |
| A plugin needs a newer OTTY       | At install: "Needs a newer OTTY (agents.agent contract 0.2)". Installed plugins keep running. |

<Aside title="Where plugins are kept">
The installed files are in `~/.local/share/otty/plugins/<id>/<version>/`, the compiled copies in
`~/.cache/otty/plugins/`, and the list with your grants and choices in `~/.config/otty/plugins.json`.
</Aside>
