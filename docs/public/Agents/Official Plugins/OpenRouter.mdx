Official, version 0.1.8, install it from `assets/plugins/openrouter/` of the OTTY repository with
**Add plugin from folder…** ([how](../../plugins/#install-the-official-plugins)). Its own
repository will be `github.com/otty-shell/otty-plugin-openrouter`.

| Part       | Kind     | Gives                                                  |
| ---------- | -------- | ------------------------------------------------------ |
| OpenRouter | provider | **Key limit**: how much of the key's limit was used.   |

| Request                                  | With                         | When                                 |
| ---------------------------------------- | ---------------------------- | ------------------------------------ |
| `GET https://openrouter.ai/api/v1/key`   | The key in `Authorization`. | Every read of the account's numbers. |

It has no accounts yet. No agent of this plugin keeps a login, and a provider part never reads the
profiles of another plugin, so an OpenRouter key in the settings of Claude Code (with
`ANTHROPIC_BASE_URL` set to `https://openrouter.ai/api`) or in OpenCode is no account. The answers such a
profile sends to `openrouter.ai` are still priced as OpenRouter's, at API prices, on the profile.
Accounts will come with **Paste a key** in Add account, which is shown but not offered yet: OTTY
will keep the key in the system keyring and give the part only a handle, under the slot `key`. It
reads no files and runs nothing.

**Open usage page** opens `openrouter.ai/activity`. Its icon is a letter icon until a logo that may
be shipped is found.

## What it asks you for

Nothing while it has no accounts. For a key OpenRouter refuses, the part has the need **The
key was refused**, labelled "OpenRouter plugin", in all ten languages of OTTY, with **Open openrouter.ai**,
`https://openrouter.ai/settings/keys`, where you make a new key.
