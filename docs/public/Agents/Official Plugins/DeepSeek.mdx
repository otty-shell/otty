Official, version 0.1.7, install it from `assets/plugins/deepseek/` of the OTTY repository with
**Add plugin from folder…** ([how](../../plugins/#install-the-official-plugins)). Its own
repository will be `github.com/otty-shell/otty-plugin-deepseek`.

| Part     | Kind     | Gives                                  |
| -------- | -------- | -------------------------------------- |
| DeepSeek | provider | **Left**: the money left on the account. |

| Request                                    | With                         | When                                  |
| ------------------------------------------ | ---------------------------- | ------------------------------------- |
| `GET https://api.deepseek.com/user/balance` | The key in `Authorization`. | Every read of the account's numbers.  |

It has no accounts yet. No agent of this plugin keeps a login, and a provider part never reads the
profiles of another plugin, so a DeepSeek key in the settings of Claude Code (with
`ANTHROPIC_BASE_URL` set to `https://api.deepseek.com/anthropic`) or in OpenCode is no account. The answers such a
profile sends to `api.deepseek.com` are still priced as DeepSeek's, at API prices, on the profile.
Accounts will come with **Paste a key** in Add account, which is shown but not offered yet: OTTY
will keep the key in the system keyring and give the part only a handle, under the slot `key`. It
reads no files and runs nothing.

**Open usage page** opens `platform.deepseek.com/usage`. Its icon is a letter icon until a logo that
may be shipped is found.

## What it asks you for

Nothing while it has no accounts. For a key DeepSeek refuses, the part has the need **The
key was refused**, labelled "DeepSeek plugin", in all ten languages of OTTY, with **Open platform.deepseek.com**,
`https://platform.deepseek.com/api_keys`, where you make a new key.
