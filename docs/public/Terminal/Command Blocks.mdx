OTTY splits the terminal history into **blocks**: one block per command, with the prompt, the
command you typed and everything it printed. A block knows how its command ended and how long it
ran, so you can jump between commands, fold long output and copy exactly one command's output.

<Demo scene="blocks" caption="Product demo: a long test run, a failed command, jumping between blocks and folding one" />

## What you can do

| Do                       | How                                                                                              |
| ------------------------ | ------------------------------------------------------------------------------------------------ |
| Select a block           | Right-click it, or use the keys below. Right-click also opens the block menu.                    |
| Go to the previous block | <kbd>Ctrl</kbd> <kbd>Shift</kbd> <kbd>↑</kbd> on Linux, <kbd>Cmd</kbd> <kbd>↑</kbd> on macOS. With no block selected, it selects the latest one. |
| Go to the next block     | <kbd>Ctrl</kbd> <kbd>Shift</kbd> <kbd>↓</kbd> on Linux, <kbd>Cmd</kbd> <kbd>↓</kbd> on macOS.    |
| Fold or unfold a block   | The arrow on its status line, or **Collapse** / **Expand** in the right-click menu. A folded block keeps its command and shows "N lines hidden". |
| Copy the output          | Right-click the block → **Copy content**.                                                        |
| Copy the command         | Right-click the block → **Copy command**.                                                        |
| Run the command again    | Right-click the block → **Run again**. OTTY types the command at the prompt; it is offered only while the shell waits at the prompt. |

## How it works

A terminal on its own sees only a stream of characters; it can not tell where one command's output
ends and the next prompt begins. So OTTY adds small **hooks** to zsh and bash. Before each prompt
and right before each command, the hook sends OTTY an invisible message with what happened.

| Message   | The shell sends it                                  | It carries                          | OTTY                                                        |
| --------- | --------------------------------------------------- | ----------------------------------- | ----------------------------------------------------------- |
| `precmd`  | Before every prompt.                                | block id, current folder, time      | Starts a prompt block and tells the Files panel the folder. |
| `preexec` | After you press Enter, before the command runs.     | block id, command, folder, time     | Starts a command block in the running state.                |
| `exit`    | At the next prompt, for the command that just ran.  | block id, exit code                 | Ends the block with its exit code and duration.             |

Each message is a DCS escape sequence (a "device control string", a kind of message a terminal reads
but does not print) with a JSON body in hexadecimal:

```text
ESC P otty-dcs;block;<JSON as hex> ESC \
```

```json
{
  "v": 1,
  "id": "cmd-4242-7",
  "phase": "preexec",
  "cmd": "cargo test",
  "cwd": "/home/dev/otty",
  "time": 1763548800
}
```

The hexadecimal form keeps quotes, `;` and control characters of a command from breaking the
sequence. OTTY reads at most 4096 bytes of JSON per message. The ids hold the process id of the
shell, so a shell started inside another one never ends the blocks of its parent.

### How OTTY adds the hooks

OTTY never edits your shell files. It starts the shell with a small wrapper that first loads your own
startup file and then the OTTY hooks:

| Shell | How                                                                                                     | Your file           |
| ----- | ------------------------------------------------------------------------------------------------------- | ------------------- |
| zsh   | Sets `ZDOTDIR` to a folder of OTTY whose `.zshrc` loads your `.zshrc` (from your own `ZDOTDIR` or home), then `otty.zsh`. | unchanged |
| bash  | Starts bash with `--rcfile` set to a wrapper that loads `~/.bashrc`, then `otty.bash`. The bash hooks use a small copy of [bash-preexec](https://github.com/rcaloras/bash-preexec) and keep your `PROMPT_COMMAND`. | unchanged |

The hooks load only in an interactive shell, and only once per shell. They need `od` and `tr`, which
every Linux and macOS system has. To write the JSON they use `jq`, `python3`, `python` or `perl`,
whichever is installed, and their own slower code when none is.

## Where blocks work

| Where                                                  | Blocks                                       | What you get                                                               |
| ------------------------------------------------------ | -------------------------------------------- | -------------------------------------------------------------------------- |
| zsh or bash in an OTTY tab                             | <Badge text="yes" variant="success" />       | A block per command.                                                       |
| A full-screen program: `vim`, `htop`, `less`           | <Badge text="yes" variant="success" />       | The program takes the whole pane while it runs; then its command is a normal block again. |
| Another shell: fish, nushell, PowerShell               | <Badge text="no" variant="caution" />        | The terminal works as usual; the history is one plain block.               |
| A remote shell over SSH                                | <Badge text="no" variant="caution" />        | OTTY brings no hooks to the remote machine, so the whole remote session is one block. |

<Aside>
Blocks also tell OTTY the current folder: the **Files** panel follows the folder of the focused
pane. A pane without hooks reports no folder, so the panel stays where it was.
</Aside>
