# Blocks v2: задачи по фазам

Этот каталог разбивает общий [roadmap](../blocks-v2.md) на отдельные задачи, которые можно
брать в работу и проверять независимо. Нумерация фаз совпадает с этапами 0–10 раздела 14 и с
рекомендуемыми PR из раздела 15 общего документа.

## Как читать статусы

- **Частично выполнено** — в текущем рабочем дереве есть часть результата, но все критерии
  фазы ещё не выполнены.
- **Не начато** — может существовать подготовительная инфраструктура, но целевой результат
  фазы отсутствует.
- **Выполнено** разрешается поставить только после выполнения всех checklist-пунктов,
  автоматических проверок и ручного сценария из файла фазы.

Текущая реализация выросла из первого вертикального среза раздела 17 roadmap. Она пересекает
фазы 0–7; автоматический scope фазы 0 выполнен, но фаза ожидает обязательное ручное
GUI-подтверждение. Следующие изменения должны продолжать незавершённые пункты остальных фаз.

Подробный состав и ручная проверка уже реализованной итерации зафиксированы отдельно:
[первый вертикальный срез от 2026-08-09](implemented-slice-2026-08-09.md).

## Решение по protocol v1

- Protocol v1 не является публичным compatibility mode и не остаётся в production
  вместе с v2.
- Runtime switch `v1/v2`, migration window и compatibility adapter не реализуются.
- После прохождения v2 acceptance matrix старые emitter, parser, actions и lifecycle path
  удаляются до релиза в той же финальной итерации.
- Rollback выполняется установкой предыдущего application artifact, а не совместным
  существованием двух protocol paths в одном бинарнике.
- Legacy v1 DCS после удаления не создаёт блоки и безопасно игнорируется общим
  DCS parser-ом.

## Общие правила выполнения

1. Соблюдать dependency order: следующая фаза не должна маскировать незакрытые инварианты
   предыдущей.
2. Для business logic сначала добавлять падающие тесты, затем реализацию.
3. Не добавлять dependency без предварительного согласования с пользователем.
4. Не включать command/output в обычные logs, diagnostics и benchmark reports.
5. После каждой фазы обновлять статус её файла и общий [roadmap](../blocks-v2.md).
6. Перед закрытием любой фазы выполнять её ручной сценарий на реальном приложении, а не
   ограничиваться unit-тестами.
7. Запускать `cargo llvm-cov --workspace --all-features` до и после изменений одной и той же
   командой; общий line coverage не должен снижаться. Фиксированный минимальный процент не
   применяется.
